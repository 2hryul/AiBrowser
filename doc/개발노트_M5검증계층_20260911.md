- **결정 사항**
  - **오탐 0 은 규칙의 영리함이 아니라 구조로 만든다.** `Verifier` 에 판정을 올리는 길을 두지
    않았다. 규칙 실패 → 심각도대로 FAIL/REVIEW, 통과해도 근거에 `source: 'llm'` 이 섞이면
    PASS → REVIEW(강등은 한 곳에서만)
  - **퍼지 매칭은 언제나 `review: true`**, **`normalizeId` 는 혼동 문자를 접지 않는다**
    (`O`→`0` 금지). 매칭률은 떨어지지만 서로 다른 식별자를 같다고 말하지 않는다
  - **오라클을 겹쳐 붙인다.** 합계만 보면 서로 상쇄되는 두 오류를 놓친다(미탐). 최소 3개
    요구에 5개를 붙였고, REVIEW 비율은 규칙을 더해 낮출 문제로 남긴다(LLM 신뢰도 조정 금지)
  - **승격은 오라클을 만들어 주지 않는다.** 기록에서 짐작한 오라클은 첫 실행 결과를 그대로
    "정답" 으로 굳힌다 — 그 실행이 틀렸으면 틀림이 기준이 된다. 빈 `oracles` 는 로드 거부이므로
    저장도 막힌다
  - **증거 팩 마스킹은 어댑터가 선언한 `pii` 경로만 본다.** 전역 `maskDeep` 은 사번 패턴
    (연속 7자리)이 `1250000` 같은 금액을 함께 가려 대사 근거를 지운다
  - **어댑터는 값을 고르지 않는다.** 화면과 파일 금액이 어긋나면 `sourceConflict` 로 표시하고
    판정은 오라클에 맡긴다. "파일이 더 정확하니 파일을 쓰자" 를 어댑터가 정하면 두 시스템이
    어긋난 사실이 사라진다
  - **워크플로우에 식 계산을 넣지 않는다.** `${경로}` 참조만 지원하고 합계는 `aggregate` 단계로
    드러내 놓는다. 작은 언어를 심으면 그 언어의 버그가 판정의 버그가 된다
  - **eval 은 Playwright 테스트가 아니라 독립 스크립트.** 종료 코드가 CI 판정이어야 한다
  - xlsx 는 **의존성 없이 직접 구현**한 것을 그대로 쓴다(exceljs 가 라이선스 미표기 패키지를
    끌어온다 — 2026-09-10 결정). M5 에서 새 의존성은 0개

- **실측으로 잡은 결함**
  1. **폴백 경로가 계약과 다른 모양을 내면 판정이 바뀐다.** 정산 화면 표에 날짜 칸이 없어
     `dom` 폴백 행에서 `date` 가 빠지고, `normalize` 가 터져 **정상인 날이 FAIL** 로 나왔다.
     요청 날짜를 채우게 고치고, "API 가 죽은 채로 20일치를 돌려도 판정이 같다" 를 테스트로 고정
  2. **`run.json` 출력 요약에 결재자 이름이 남았다.** 대사 매칭이 어댑터 행을 임의 깊이로
     품는데 경로 마스킹은 그 모양을 적을 수 없다. `pii` 경로의 마지막 조각을 이름으로 보고
     트리 전체를 훑는 마스킹을 더했다
  3. **경로로 꺼낸 값이 출처를 잃었다.** `recon.onlyLeft` 같은 이름은 값 표에 없어 출처가
     `const` 로 잡혔고, `llm` 출처 목록의 항목을 근거로 쓴 오라클이 PASS 강등을 건너뛸 수
     있었다. 조회를 `values.ts` 한 곳에 모으고 머리에서 출처를 물려받게 했다
  4. **정산 화면에는 표가 둘이다**(XHR 표 + 정적 표, 같은 머리글). 두 번째 머리글 줄을 데이터로
     읽어 `거래번호`가 `"거래번호"` 인 행이 생겼다. 반복 머리글은 건너뛰고, 머리글을 아예 못
     찾으면 빈 배열이 아니라 `null` 을 돌려준다 — "0건" 과 "화면이 바뀜" 은 다르다
  5. **규칙에도 버전이 필요하다.** 규칙을 고치면 같은 데이터가 다른 판정을 낸다.
     `Rule.version` → `OracleOutcome` → `oracles.json`·`run.json`
  - 첫 `npm run smoke` 에서 `[M1] 탭 고급` 이 한 번 실패했다가 재실행 통과 — 앞선 Electron 이
    단일 인스턴스 잠금을 쥔 것이고 코드 문제는 아니었다. `scripts/eval.ts` 는 시작할 때 남은
