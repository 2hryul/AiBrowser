# ADR 0001 — Vessel 포크 vs 신규 구현 (M0 한정 결정)

- 상태: 부분 결정 (M0 범위에서만 확정, 최종 결론은 보류)
- 날짜: 2026-09-10
- 관련: `GOAL.md`(M0), `CLAUDE.md` 불변 조건 1·9, 마일스톤 표

## 맥락

Helm 은 "사람은 크롬처럼 쓰고 AI 는 사람처럼 다루는" 사내 브라우저다.
출발점으로 두 가지가 있었다.

1. Vessel Browser(MIT)를 포크해 세션·체크포인트·북마크 메타·승인 구현을 물려받는다.
2. electron-vite 로 신규 스캐폴딩을 만든다.

포크 판단에는 Vessel 의 Windows 빌드로 사내 포털 3종 렌더링·세션 유지·MCP 시나리오 A 를
실제로 돌려본 결과가 필요하다. 그 검증 자체가 별도 세션 분량이다.

## 결정

**M0 는 신규(greenfield) 스캐폴딩으로 만든다.** Vessel 포크 여부는 M0 산출물을 눈으로 확인한 뒤
별도 세션에서 다시 판단한다. M0 진행 도중에는 판단하지 않는다.

M0 에 한해 함께 확정한 것:

- **LLM·MCP·ToolSurface 제외.** M0 결과물은 "AI 가 없는, 뜨는 빈 브라우저"다.
  ToolSurface 계약(`CLAUDE.md`)은 M2 에서 도입한다.
- **테스트는 외부 접속 없이 번들 로컬 페이지로만.** 커스텀 프로토콜 `app://home/` 로
  `resources\home\index.html` 을 서비스한다. 사내 포털·공개 사이트에 붙지 않는다.
- **electron-builder 미도입.** M0 의 `build` 는 `electron-vite build`(= `out\`)까지다.
  NSIS 인스톨러와 `VERSION` 파일 기반 버전 주입은 산출물이 생기는 M1/M6 에서 함께 넣는다.
- **탭 관리는 `BaseWindow` + `WebContentsView`.** `BrowserWindow` + `BrowserView` 는
  Electron 이 대체를 권고한 조합이라 처음부터 쓰지 않는다.

## 근거

- 포크 결정을 미루는 비용보다, 포크 검증 없이 포크에 올라타는 비용이 크다.
  M0 스캐폴딩은 어느 쪽으로 가든 버려지는 양이 작다(탭 관리 + 프로토콜 + 셸).
- 신규 스캐폴딩은 `CLAUDE.md` 보안 기본값(`contextIsolation`/`sandbox`/preload 금지)을
  처음부터 강제할 수 있다. 포크는 기존 설정을 감사해야 한다.
- 외부 접속 없는 테스트는 재현 가능하고 사내망 정책과 무관하게 돈다.

## 결과

- `src\main\browser\{TabManager,Omnibox,AppProtocol,Shortcuts}.ts` 가 M0 의 전부다.
- 웹 콘텐츠 `WebContentsView` 에는 preload 를 붙이지 않는다. 셸만 preload 를 갖는다.
- IPC 는 `src\main\ipc\channels.ts` 화이트리스트만 노출한다.
- 세션은 `persist:helm` 파티션 하나(`Named Session` 이름 `default`)로 시작한다.
  이름 있는 세션 여러 개는 M4 `SessionStore` 에서 확장한다.

## 다시 볼 시점

M0 산출물(`artifacts\m0\REPORT.md`)을 확인한 직후. Vessel Windows 빌드로
사내 포털 3종 렌더링·세션 유지·MCP 시나리오 A 를 돌린 결과를 첨부해 이 ADR 을 갱신한다.
