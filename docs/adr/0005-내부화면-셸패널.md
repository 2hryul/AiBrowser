# ADR 0005 — 내부 화면(히스토리·다운로드·북마크·읽기 모드)은 셸 패널로 구현한다

- 상태: 결정
- 날짜: 2026-09-10
- 관련: `CLAUDE.md` 보안 기본값, `goals/GOAL-M1.md` IN SCOPE, `docs/shortcuts.md`

## 맥락

크롬은 `chrome://history`, `chrome://downloads` 처럼 내부 화면을 **탭에 열리는 페이지**로 만든다.
그 페이지들은 특권 API 를 쓰기 때문에 일반 웹 페이지와 다른 권한을 갖는다.

Helm 에서 같은 방식을 쓰려면 웹 콘텐츠를 띄우는 `WebContentsView` 에 preload 를 붙여
`window.helm` 같은 특권 표면을 노출해야 한다. 그런데 `CLAUDE.md` 보안 기본값은
**"웹 페이지 WebContentsView 에 preload 금지"** 를 못박고 있다. 탭 하나에만 preload 를 붙이는
예외를 두면, 그 탭이 임의 URL 로 이동할 때 특권 표면이 외부 페이지에 노출되는 경로가 생긴다.

## 결정

히스토리·다운로드·북마크 관리자·읽기 모드는 **셸(브라우저 크롬)이 그리는 패널**로 만든다.
탭에 열리는 페이지가 아니다.

- 셸은 이미 preload 를 가진 단 하나의 `WebContentsView` 다. 특권 표면이 여기서 벗어나지 않는다.
- 패널이 열리면 메인이 `TabManager.setContentHidden(true)` 로 탭 뷰를 숨긴다.
  탭 뷰는 `contentView` 에서 셸보다 위에 있어서, 숨기지 않으면 패널이 가려진다.
- `Esc` 또는 패널의 닫기 버튼으로 닫으면 탭 뷰가 다시 보인다.
- 내부 화면에는 `app://` 주소를 주지 않는다. 주소창에 내부 화면 URL 을 입력하는 경로 자체를
  만들지 않는다.

## 결과

- `src/renderer/src/components/panels/` 에 `PanelFrame` 공통 껍데기와 4개 화면.
- `ShellState.panel` 이 `'none' | 'history' | 'downloads' | 'bookmarks' | 'reader'` 중 하나.
- 단축키는 크롬과 같지만(`Ctrl+H`/`Ctrl+J`/`Ctrl+Shift+O`) 결과가 탭이 아니라 패널이다.
  이 차이는 `docs/shortcuts.md` 의 "의도적으로 다르게 둔 것" 에 적었다.
- 내부 화면에는 탭 히스토리(뒤로/앞으로)가 없다. 패널은 탐색 스택에 들어가지 않는다.

## 감수한 것

- 크롬 사용자가 `Ctrl+H` 를 눌러 "새 탭에 기록 페이지" 를 기대하면 다르게 느낀다.
  대신 패널은 현재 탭을 잃지 않고 열리고 닫힌다 — 기록에서 링크를 눌러 현재 탭으로 이동하는
  흐름이 오히려 짧다.
- 내부 화면을 북마크하거나 링크로 공유할 수 없다. 사내 브라우저에서 필요한 기능이 아니다.

## 대안으로 검토했다가 버린 것

1. **탭 하나에만 preload 를 붙이고 URL 을 고정한다.** `will-navigate` 로 이동을 막아야 하고,
   리다이렉트·`window.open`·iframe 경로를 전부 막아야 한다. 방어 지점이 많아 보안 기본값을
   지키는 비용이 패널보다 크다.
2. **내부 화면 전용 세션 + 커스텀 프로토콜.** 특권 표면을 노출하는 preload 는 여전히 필요하다.
   프로토콜만 분리해도 근본 문제가 남는다.
3. **패널을 별도 `WebContentsView` 로 띄운다.** preload 를 가진 뷰가 둘로 늘어난다.
   셸 하나로 충분한데 표면을 늘릴 이유가 없다.

## 다시 볼 시점

M2 에서 ToolSurface 를 붙일 때. AI 가 내부 화면을 "보고" 조작해야 할 필요가 생기면
(예: AI 가 다운로드 목록을 읽음) 도구로 노출하면 되고, 화면 구조를 바꿀 필요는 없다.
